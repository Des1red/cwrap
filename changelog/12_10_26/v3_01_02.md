# Changelog

## [v3.1.2]

### Added

- **`httpintel` package structure**: `Learn` now delegates to focused, independently testable functions — `learnStatus`, `learnHeaders`, `learnContentType`, `learnSecurityHeaders`, `learnTech` — instead of one monolithic function.
- **Tech fingerprinting (`tech.go`)**: expanded header coverage for Vercel, Cloudflare, Fastly, and CloudFront. Session-cookie-name fingerprinting for common backend frameworks (PHP, Laravel, Express, Django, ASP.NET, Ruby/Rack, Rails). Infrastructure trace headers (`X-Vercel-Id`, `CF-RAY`, `X-Served-By`, `X-Amz-Cf-Pop`) are resolved to stable, human-readable locations (region/colo/POP) via a shared `infraTraceRule` mechanism, instead of storing the raw per-request trace ID that rotates on every probe.
- **Permissive CORS detection (`headers.go`, `knowledge`)**: `ent.HTTP.CORSPermissive` and `ent.HTTP.CORSOrigin` flag responses that allow credentialed cross-origin requests from any origin — either a wildcard `Access-Control-Allow-Origin` combined with `Access-Control-Allow-Credentials: true`, or an `Allow-Origin` that reflects the request's `Origin` header verbatim. Backed by `SigPermissiveCORS`.
- **CORS reflection probing (`behavior/param_expand.go`)**: `expandCORS` sends a GET carrying a deliberately fake `Origin` header (`https://cors-probe.cwrap.invalid`, using the RFC 2606-reserved `.invalid` TLD) on every entity, so `httpintel`'s reflection check has real input to evaluate rather than only detecting the wildcard+credentials case.
- **Missing security headers detection (`security_headers.go`, `knowledge`)**: flags absence of `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, and `Strict-Transport-Security` on HTML-serving responses. Backed by `SigMissingSecurityHeaders` and `ent.HTTP.MissingSecurityHeaders`.
- **CSP `frame-ancestors` awareness**: a `frame-ancestors` directive in `Content-Security-Policy` suppresses the missing-`X-Frame-Options` finding, since it's a valid modern equivalent. A permissive `frame-ancestors *` is separately flagged via `SigPermissiveFrameAncestors` and recorded in `ent.HTTP.FrameAncestors`.
- **Auth scheme extraction (`headers.go`, `knowledge`)**: `ent.HTTP.AuthScheme` captures the scheme advertised in a `WWW-Authenticate` challenge (`bearer`, `basic`, `digest`), distinct from the per-identity `AuthScheme` already tracked on `knowledge.Identity`.
- **`knowledge` package**: new `HTTPIntel` fields (`CORSPermissive`, `CORSOrigin`, `MissingSecurityHeaders`, `FrameAncestors`, `AuthScheme`) and new signals (`SigPermissiveCORS`, `SigMissingSecurityHeaders`, `SigPermissiveFrameAncestors`).
- **`report` package rendering**: entity blocks now surface `CORSOrigin`, `FrameAncestors`, `MissingSecurityHeaders`, and `AuthScheme` in the vitals block. Findings and next-steps derive from the new signals, with next-steps phrased as offensive testing actions (e.g. "Attempt clickjacking via iframe embedding from an untrusted origin") rather than remediation advice.
- **Test coverage**: full unit test coverage added across `httpintel` (tech fingerprinting, CORS, security headers, content-type parsing, auth scheme) and `behavior` (`analyzeIDOR`, `analyzeParamBehavior`, `analyzeObjectAccessSurface`, `analyzeCredentiallessIssuance`, `analyzeTokenValidation`, `detectAuthBoundary`, `detectRoleBoundary`, `analyzeOwnership`).
- **`contentType.go`**: content-type parsing now uses the standard library's `mime.ParseMediaType`, with a fallback to manual parsing for malformed headers.

### Fixed

- **CSRF cookie detection (`httpintel/headers.go`)**: the entity-level `CSRFPresent` check matched `"csrf"`/`"xsrf"` against the entire raw `Set-Cookie` header value (name, value, and attributes concatenated), which could false-positive on a cookie whose *value* happened to contain the substring. Now matches against the parsed cookie name only, consistent with the identity-level CSRF detection in `behavior/identity_extract.go`.
- **Ownership IDOR unreachable (`behavior/analyze_idor.go`)**: a loop-level `continue` guarding the structural-diff comparison also skipped the independent ownership-based IDOR check below it. A param with strong `OwnershipBoundary` evidence but fewer than two distinct probed values (common — many params are only tested with one alternate value before this analyzer runs) never got promoted to `PossibleIDOR`, regardless of how strong the underlying evidence was.
- **Synthetic identity conflated with genuine auth (`behavior/detect.go`)**: `detectAuthBoundary` counted any credentialed 200 response toward "authenticated success," including from synthetic identities like `corrupted-token`. A corrupted token that happened to be accepted — itself a broken-token-validation finding — was being misreported as ordinary authenticated access instead. Now excludes synthetic identities from this check via `shouldCompareIdentity`.
