# Changelog

```07-05-26``` ```v2.8.1```

### Added

- Added JWT cookie corruption support during recon.
  - Introduced `corrupted-cookie-token` synthetic identity.
  - Recon now mutates JWT cookie signatures and checks whether protected endpoints still accept them.
  - Accepted corrupted JWT cookies now trigger `BrokenTokenValidation`.

- Added opaque session/token cookie corruption support during recon.
  - Introduced `corrupted-opaque-cookie-token` synthetic identity.
  - Recon now detects auth-like non-JWT cookies such as `session_id`, `sid`, `auth`, `token`, and `remember`.
  - Modified opaque cookies are tested against protected endpoints.
  - Accepted corrupted opaque cookies now trigger `WeakOpaqueTokenValidation`.

- Added dynamic identity refresh after session capture.
  - If new auth cookies are discovered during probing, recon can add the relevant corrupted-cookie identity during the same run.
  - Already-seen entities are requeued with `identity refresh` so new identities are tested against previously discovered endpoints.

- Added `ReasonIdentityRefresh` probe reason.
  - Prevents refreshed identity probes from being deduplicated against earlier `identity probe` requests.

- Added shared token helper logic.
  - `tokens.LooksLikeJWT`
  - `tokens.LooksLikeOpaqueAuthCookie`
  - `tokens.CorruptSignature`

### Changed

- Improved synthetic identity handling.
  - Synthetic identities are now excluded from normal ownership, IDOR, and role-boundary comparisons.
  - Corrupted token identities are used only for token-validation evidence.
  - This prevents scanner-created identities from creating false `RoleBoundary`, `ObjectOwnership`, or `PossibleIDOR` findings.

- Updated identity comparison logic.
  - Added `shouldCompareIdentity` for real credentialed identity checks.
  - Updated `isComparableIdentity` to exclude synthetic identities and the baseline live session where appropriate.

- Improved `fake-admin` behavior.
  - `fake-admin` now removes bearer tokens and cookies before adding spoofing headers.
  - This makes it a true credentialless header-spoofing probe instead of “real session + fake header”.

- Improved role-boundary accuracy.
  - Role boundary now reflects real authenticated permission denial.
  - Rejected corrupted credentials no longer count as role boundaries.

- Improved report output.
  - Added finding text for weak opaque token/session validation.
  - Added next-step suggestions for opaque session validation issues.

### Fixed

- Fixed false role-boundary inflation caused by synthetic corrupted-token identities.
- Fixed false ownership/IDOR findings caused by comparing synthetic identities against real identities.
- Fixed same-run coverage gap where JWT cookies discovered during recon were not tested until a later run.
- Fixed identity refresh probe deduplication by using a distinct probe reason.
- Fixed JWT shape checks by centralizing detection through `tokens.LooksLikeJWT`.

### Notes

- JWT corruption and opaque cookie corruption are intentionally separate:
  - `BrokenTokenValidation` means a tampered JWT was accepted.
  - `WeakOpaqueTokenValidation` means a modified non-JWT auth/session cookie was accepted.
- Recon still performs lightweight validation only. Strong JWT exploit checks such as role swap and `alg=none` remain part of the exploit phase.
