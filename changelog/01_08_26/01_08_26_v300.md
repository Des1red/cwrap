# Changelog

## [v3.0.0]

### Added

* Added abnormal response detection for active probes.
* Added per-identity response evidence collection containing:

  * Request URL
  * HTTP method
  * Status code
  * Content type
  * Full response body
* Added deterministic probe reference selection.

  * Prefers an identity that sent no credentials.
  * Falls back to the first valid response using identity execution order.
* Added abnormal response storage to each recon entity.
* Added deduplication using:

  * Method
  * URL
  * Status
  * Response fingerprint
* Added scan-specific abnormal response directories under `reports/`.
* Added exact abnormal response body files with restricted `0600` permissions.
* Added abnormal response counts to:

  * Terminal recon summary
  * Full report global statistics
* Added tests for abnormal response recording.
* Added tests for deterministic probe references and updated probe-impact analysis.
* Added path-parameter impact test coverage.

### Changed

* Replaced the previous string-only probe reference with a structured `probeReference`.
* Probe references now include:

  * Identity name
  * Response fingerprint
  * Response evidence
* Updated `markEffectiveIdentities` to use the structured reference.
* Updated `learnProbeImpact` to use the structured reference.
* Fixed `learnProbeImpact` so path-parameter probes can increase parameter interest.
* Changed abnormal response deduplication so identical response bodies received by multiple identities are stored only once.
* Changed report file handling to explicitly close the main report before writing abnormal response artifacts.
* Kept SPA fallback fingerprinting separate from abnormal response detection.

### Detection Logic

An abnormal response is currently recorded only when:

1. The response is not classified as an SPA fallback.
2. Its exact status-and-body fingerprint differs from the deterministic reference response.
3. Its body is substantially larger than the reference response.

Current size thresholds:

* Ignore differences smaller than 4 KB.
* When the reference is smaller than 512 bytes, require a response of at least 8 KB.
* Otherwise, require the candidate response to be at least three times larger than the reference.

### Report Output

Abnormal response bodies are written beside the main report:

```text
reports/
├── target_timestamp.report
└── target_timestamp_abnormal_responses/
    ├── 001_get_session_200.response
    └── 002_get_admin_200.response
```

The response files contain the exact body received by CWRAP.

### Fixed

* Fixed nondeterministic probe reference selection caused by iterating over Go maps.
* Fixed unreachable path-parameter impact logic caused by the old query-only guard.
* Prevented SPA shell responses from entering abnormal response analysis.
* Prevented duplicate abnormal response files for identical responses across identities.

### Notes

* Abnormal response detection only analyzes requests generated by CWRAP.
* It does not currently capture browser-generated runtime traffic such as Firebase SDK requests.
* Runtime interception would require a separate proxy or browser instrumentation mode.
