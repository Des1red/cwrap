# Changelog

## [v3.1.4]

### Added

- **`transport`: retry on client-side timeout for safe methods.** `Do` now retries once, with a longer timeout, when the initial request times out — but only for `GET`, `HEAD`, and `OPTIONS`. Mutating methods (`POST`, `PUT`, `PATCH`, `DELETE`) are excluded deliberately: a timeout doesn't tell you whether the original request completed server-side before the client gave up on the response, so retrying a mutation risks a double-submit. Retry attempts are logged when `--debug` is set.
- **`behavior`: `corruptedCookieIdentity` helper.** JWT-signature-corrupted and opaque-cookie-corrupted synthetic identities are now built through one shared constructor instead of four separate, near-identical closures spread across `identity.go`.
- **Admin surface: dedicated report section for unconfirmed leads.** Entities carrying the `AdminSurface` signal but with no confirmed HTTP evidence behind it — either because every probe returned the same SPA-fallback shell as the scan's base page, or because every probe failed outright — now get their own report section, `SECONDARY FOCUS ENDPOINTS (UNCONFIRMED — PATH PATTERN ONLY)`, separate from `ENTITY INTELLIGENCE`.
- **Test coverage (`behavior`)**: `addLiveIdentity` (registration, dedup, cookie-snapshot isolation, `Apply` behavior, requeue triggering), `discoverIdentityFromResponse` (new-identity discovery and all skip conditions), `captureSession` (all early-return branches and the non-`LiveSession` discovery delegation), `corruptJWTCookies`, and `ensureCorruptedCookieIdentity`.

### Fixed

- **`behavior`: duplicate probes from `addLiveIdentity`'s re-queue logic.** Two loops re-queued entities for a newly discovered identity with overlapping trigger conditions and different `Probe.Key()`s, so an entity qualifying for both produced two probes for the same identity-refresh event instead of being deduplicated. The second loop now skips any entity already handled by the first.
- **`transport`: silent timeouts on slow-responding targets.** The client's fixed 15-second timeout was too tight for some responses from the live test target, causing `transport.Do` to fail with no retry and no logged reason — `executeProbeIdentities` silently discards transport errors. Entities where every probe happened to time out were incorrectly reported as `"Endpoint unreachable over HTTP"` even though the endpoint was reachable, just slow. Addressed via the timeout retry described above.
- **Admin surface: signal inconsistently stripped from SPA-fallback entities (`behavior`).** `stripSPAShellSignals` deleted `SigAdminSurface` for any entity confirmed to be serving the SPA catch-all shell, while leaving the equivalent URL-pattern signal (`SigIDLikeParam`) untouched. `AdminSurface` is set from the URL path alone, before any request is sent, so a fallback response doesn't invalidate it the way it correctly invalidates response-derived signals like `AuthBoundary` or `PublicAccess`. No longer stripped.
- **Admin surface: finding text didn't distinguish confirmed from unconfirmed evidence.** `"Administrative surface detected"` is now conditional: entities where the signal is the only evidence (no confirmed HTTP behavior at all) read as `"Path suggests administrative surface (unconfirmed — endpoint unreachable over HTTP)"` instead of the flat, confirmation-implying original wording.
- **Admin surface: terminal summary count silently disagreed with the full report.** The count skipped every `IsSPAFallback` entity before checking for `SigAdminSurface`, so an unconfirmed-admin-surface entity was counted in the full report's new section but not in the terminal `Admin surfaces:` line. Counting for this signal is now a separate pass, not gated on `IsSPAFallback`, consistent with how the signal is preserved everywhere else.
