# Changelog: `jsintel`
## [v3.1.0]
Comparing the original single-file `jsintel.go` (unexported `reXxx` vars, local `JSEndpoint` type, `Learn(ent, sourceURL, body)`, pure regex extraction) against the current state (`jsintel` + `jsintel/common` + `jsintel/ast` + `jsintel/treesitter`, plus `knowledge.JSFinding*` constants).

## New functionality (behavior changes, not refactor)

- **AST-based endpoint extraction added.** Old version found endpoints purely via regex (`reFetch`, `reAxios`, `reXHR`, `rePathLiteral`) matching raw source text. New version runs a full JS parse first (`jsintel/ast`, goja-based) and a tree-sitter dataflow pass (`jsintel/treesitter`) via `ExtractEndpointsHybrid`, resolving constants, string concatenation, template literals, object properties, `axios.create` instances, `Request` constructors, class/prototype method chains, and cross-function argument flow — none of which the regex-only version could see. Regex extraction is still run afterward in `discoverEndpoints` as a supplementary pass, feeding into the same dedup set.
- **Dynamic HTTP flow tracking added.** New `knowledge.JSHTTPFlow` / `Entity.AddJSHTTPFlow` / `ent.Content.JSHTTPFlows` capture calls whose URL or method can't be statically resolved (e.g. `fetch(url, {method})` where both come from an outer scope) as symbolic flows with `URLSource`/`MethodSource`/`DynamicURL`/`DynamicMethod`. No equivalent existed in the old version — unresolved calls were previously just dropped.
- **Email detection added.** `common.ReEmail` + `learnSecrets`'s email block + `knowledge.Entity.Content...` leak recording + `Knowledge.AddEmail` are all new. The old version had no email regex or handling at all.
- **`Learn`'s signature changed**: `Learn(ent, sourceURL, body)` → `Learn(k *knowledge.Knowledge, ent, sourceURL, body)`. The new `*knowledge.Knowledge` parameter is required for the new `k.AddEmail(email)` call (global, cross-entity email dedup) — this is a functional dependency, not incidental.
- **AST-recovery findings added.** New `ast_parsed` / `ast_parse_error` / `ast_recovered` / `ast_recovery_run` / `ast_recovery_scopes` / `ast_recovery_parsed` / `ast_recovery_failed` / `http_flow` finding kinds, all new counters with no analog in the old regex-only version, reflecting the new hybrid extraction pipeline's success/failure/fallback paths.
- **`JSEndpoint` moved packages.** Old: package-local `jsintel.JSEndpoint`. New: `common.JSEndpoint`, shared across `jsintel`, `jsintel/ast`, and `jsintel/treesitter`. Same three fields (`Path`, `Method`, `Kind`), just relocated so multiple packages can produce/consume the same type.

## Structural refactor (package split, no behavior change)

- Old: everything in one file, `jsintel.go` (~280 lines) — regexes, `Learn`, `addJSEndpoint`, `appendLeak`, `redact`, `isNoiseURL`, `JSPathSuffix`, `IsPhantomJSURL`.
- New: split across `learn.go` (orchestration only) + six `learn_*.go` files, one per detection category (`learn_secrets.go`, `learn_PrivSurface.go`, `learn_FeatureFlags.go`, `learn_EnvRef.go`, `learn_Infrastructure.go`) + `discover_endpoints.go`. Regexes, `AddJSEndpoint`/`AppendJSEndpoint`/`AppendLeak`/`Redact`/`IsNoiseURL`/`JSPathSuffix`/`IsPhantomJSURL` all moved to the new `jsintel/common` package (now exported: `ReJWT`, `ReAWS`, etc., capitalized from the old unexported `reJWT`, `reAWS`).
- New `jsintel/ast` package (`astp`) holds the goja-based direct AST extractor (`ast.go`, `ast_collect.go`, `ast_handle.go`, `ast_helpers.go`, `ast_resolve.go`) — entirely new code, not a refactor of anything in the old single file.
- New `jsintel/treesitter` package holds the tree-sitter dataflow extractor — also entirely new code. Internally split  into `treesitter.go` (hybrid entry point + merge), `treesitter_dataflow.go` (types + `extractEndpointsDataFlow`), `treesitter_find.go` (`findX` extraction functions), `treesitter_bindings.go`/`treesitter_register.go` (binding construction, split apart  for size), `treesitter_resolve.go` (value resolution), `treesitter_helpers.go` (shared low-level helpers), `treesitter_walk.go` (new — the four generic tree-walker helpers extracted ), `dataflow_helpers.go` (new — `dataFlowURLSource`/`dataFlowMethodSource`/`dataFlowArgumentSource`/`mergeDataFlowCallValues`, split out of `treesitter_dataflow.go` ).

## This refactor of the `treesitter` package (zero intended behavior change)

- Added `nodeText`, `keyText` helpers; replaced ~90 occurrences of `strings.TrimSpace(node.Utf8Text(source))` and the hand-rolled quote-strip pattern across every file in the package.
- Added `forEachObjectPair`, layered on new `iterateObjectProperties`; used to collapse `findRequestMethodBinding`, `findStaticRequestMethods`, `resolveObjectStringProperties`, and (partially, via the underlying primitive) `findFetchMethodBinding`.
- Added `walkVariableDeclarators`, `walkNamedFunctionLikeNodes`, `walkAssignmentExpressions` — collapsed duplicated tree-walk skeletons in `findStringVariables`/`findAxiosClientNames`, `findNamedDataFlowFunctions`/`registerFunctionBindings`, and `findConstructorBindings`/the prototype-alias walk in `findDataFlowClasses`.
- Added `newDataFlowClass()` — collapsed two identical `dataFlowClass{...}` literal constructions in `findDataFlowClasses`.
- Added `lookupObjectValue()` — collapsed six duplicated `values.Objects[param][property]` two-step lookups across `resolveDataFlowMethods`, `resolveDataFlowPath`, `isDataFlowMethodResolved`.
- Added `withDataFlowMerge()` — collapsed the duplicated merge-and-flows block in `ExtractEndpointsHybrid`'s two return branches.
- Removed now-dead `strings` imports from `treesitter_bindings.go` and `treesitter_dataflow.go` after the `nodeText` conversion.

### Real bug found and fixed during this refactor

- **`registerFunctionBindings`'s `variable_declarator` walk was missing an identifier-kind check** that `findNamedDataFlowFunctions` already had, meaning a destructured arrow-function binding (`const { run } = () => {...}`) would silently register a garbage binding key under the shared `walkNamedFunctionLikeNodes` helper today. Confirmed via `TestFindNamedDataFlowFunctionsSkipsDestructuredArrowBinding` (new test) that the bug was benign in practice (the bogus key was never reachable at any real call site) but is now closed — both paths require a plain identifier binding.
- **A copy-paste variable-reference bug caught mid-refactor** in `findFetchMethodBinding`'s `member_expression` case: `propertyName := nodeText(property, source)` was referencing the outer loop variable `property` (the whole pair node) instead of the newly-declared `propertyNode` (the member expression's `.property` field). Caught before merge, fixed to reference `propertyNode`.

## String-literal → named-constant migration (, `knowledge` package)

- Added `knowledge/js_findings.go` with 26 exported string constants (`JSFindingPEM`, `JSFindingAWSKey`, `JSFindingJWT`, `JSFindingKeyword`, `JSFindingFirebase`, `JSFindingEmail`, `JSFindingRoleCheck`, `JSFindingPrivFlag`, `JSFindingPrivGate`, `JSFindingFeatureToken`, `JSFindingFeatureBlock`, `JSFindingFeatureToggle`, `JSFindingEnvRef`, `JSFindingEnvPublic`, `JSFindingHostURL`, `JSFindingHostInternal`, `JSFindingHostPrivateIP`, `JSFindingEndpoint`, `JSFindingASTParsed`, `JSFindingASTParseError`, `JSFindingASTRecovered`, `JSFindingASTRecoveryRun`, `JSFindingASTRecoveryScopes`, `JSFindingASTRecoveryParsed`, `JSFindingASTRecoveryFailed`, `JSFindingHTTPFlow`).
- Every `learn_*.go` file and `discover_endpoints.go` converted from raw string kind literals (`"env_ref"`, `"aws_key"`, etc.) to these constants, for both `ent.Content.JSFindings[...]` map keys and `common.AppendLeak(...)` kind arguments.
- `jsintel_test.go` deliberately left on raw string literals, per explicit decision — production code and test assertions are now decoupled on this axis; a future constant rename won't be caught by the compiler in the test file, only in production code.
- Second-tier magic strings (`"access_key_id"`, `"role"`, `"domain"`, `"if_gate"`, etc. — the `key` argument to `AppendLeak`, not the `kind`) were explicitly scoped out of this pass and remain raw literals in both old and new versions.

## Test suite changes

- Old `jsintel_test.go`: `newEnt()` returning a bare `*knowledge.Entity`; `Learn(ent, sourceURL, body)` (3 args); no email test; no dynamic-flow test; no tree-sitter-recovery test.
- New `jsintel_test.go`: `newTestContext()` returning `(*knowledge.Knowledge, *knowledge.Entity)`; `Learn(k, ent, sourceURL, body)` (4 args) throughout; added `TestDiscoverEndpointsUsesTreeSitterRecovery`, `TestLearn_EmailAddedToKnowledge`, `TestLearnStoresDynamicHTTPFlow` — all covering functionality that didn't exist in the old version.
- New `jsintel/treesitter/treesitter_test.go` and `jsintel/ast/ast_test.go` (`ast_fetch_test.go` in the original upload) are wholly new test files for wholly new packages — no old-version equivalent exists to diff against.
