# Changelog

## ```07-05-26``` ```v2.8.3``` — Probe Identity Kind and Report Grouping

### Added

- Added probe-level identity intent.
  - Introduced `ProbeIdentityKind`.
  - Added identity-kind values for:
    - `ProbeIdentityAny`
    - `ProbeIdentitySynthetic`
    - `ProbeIdentityLive`
  - Added `IdentityKind` to `knowledge.Probe`.
  - Added `IdentityKind` to `knowledge.ProbeLogEntry`.
  - Included `IdentityKind` in `Probe.Key()` so probes with different identity intent do not collide.

- Added explicit probe execution filtering by identity intent.
  - `ProbeIdentitySynthetic` runs only synthetic identities.
  - `ProbeIdentityLive` runs only real/live identities.
  - `ProbeIdentityAny` keeps normal behavior.
  - Synthetic suppression no longer accidentally blocks explicitly synthetic-only probes.

- Added synthetic identity tracking to reportable identity intel.
  - Added `Synthetic bool` to `knowledge.Identity`.
  - Added `IdentityTagSynthetic`.
  - `extractIdentity` now receives and stores whether the runtime identity is synthetic.

- Added synthetic-aware probe log metadata.
  - Probe logs can now distinguish normal probes, synthetic refresh probes, and live identity refresh probes.
  - Probe log output can show labels such as:
    - `identity refresh/synthetic`
    - `live identity refresh:member-uid-2/live`

- Added endpoint grouping for entity intelligence.
  - Introduced `entityGroup`.
  - Added `entityGroupKey` to group concrete endpoints by route family.
  - Numeric path segments are grouped under `{id}`.
  - Numeric query values are grouped under `{id}`.
  - Example groups:
    - `/api/notes/1`, `/api/notes/2`, `/api/notes/3` -> `/api/notes/{id}`
    - `/api/orders?user_id=1` -> `/api/orders?user_id={id}`

- Added grouped next steps.
  - Next steps are now collected once per endpoint group instead of repeated under every concrete entity.
  - Each grouped next step records which concrete entity produced it.

- Added route tree output.
  - Route tree groups entities by path hierarchy.
  - This makes related endpoints such as `/api/notes/1`, `/api/notes/2`, and `/api/notes/3` easier to read together.

- Added a small report writer helper.
  - Introduced a writer helper for indentation and consistent line formatting.
  - This replaces manual tabs and uneven spacing in report sections.

### Changed

- Live identity refresh probes are now explicitly marked as live-only.
  - `addLiveIdentity` now queues refresh probes with `ProbeIdentityLive`.
  - This prevents synthetic identities from running during live identity replay.

- Synthetic refresh probes are now explicitly marked as synthetic-only.
  - Corrupted-cookie and corrupted-opaque-cookie refresh probes now use `ProbeIdentitySynthetic`.
  - This prevents live identities from being rerun during synthetic-token refresh workflows.

- Probe log rendering now includes identity intent labels.
  - Probe logs are easier to understand when debugging why an identity was run.
  - Live identity replay and synthetic identity replay are now visible in the report.

- Entity identity output now labels synthetic identities.
  - Synthetic identities now show `synthetic` in the identity tag list.
  - Rejected synthetic identities no longer display misleading parsed role/uid/expiry claims.
  - Accepted synthetic identities still display claims, which is useful for token-validation findings.

- Entity intelligence is now organized by endpoint group.
  - The existing per-entity details are preserved.
  - Concrete entities are now printed under a shared endpoint group.
  - This keeps important detail while improving readability.

- Group next steps now replace repeated per-entity next-step blocks.
  - The report still keeps entity-level findings.
  - Repetitive next steps are deduplicated and printed once at the end of the endpoint group.

- Report formatting now uses consistent indentation.
  - Report sections are easier to scan.
  - Manual tab alignment is being replaced with controlled indentation.

### Fixed

- Fixed ambiguity between synthetic and live identity refresh probes.
  - Before this change, refresh probes could only be understood from their reason string or identity name.
  - Probe identity intent now makes the execution purpose explicit.

- Fixed probe-key collisions between identity intent categories.
  - `Probe.Key()` now includes `IdentityKind`.
  - A live identity refresh and a synthetic identity refresh for the same URL/reason no longer collide.

- Fixed report confusion around corrupted-token identities.
  - Rejected corrupted-token identities no longer print misleading claims such as `role=owner` or `uid=3`.
  - Reports now clearly mark these as synthetic rejected identities.

- Fixed repeated next-step noise in grouped endpoint families.
  - Related concrete endpoints no longer repeat the same next-step block independently.
  - Next steps are collected per group with source URLs.

- Fixed readability problems caused by flat entity ordering.
  - Entity intelligence can now be grouped by route family instead of showing every concrete path as a separate unrelated top-level block.

### Notes

- `IdentityKind` and `ProbeIdentityKind` serve different purposes:
  - `IdentityKind` describes what the response showed about an identity.
  - `ProbeIdentityKind` describes which class of identities a probe is intended to run.
- `behavior.Identity.Synthetic` is still needed.
  - It describes the identity itself.
  - `ProbeIdentityKind` uses that property to decide whether an identity should run for a given probe.
- Endpoint grouping is a report-layer improvement only.
  - Concrete entities, probes, and evidence remain unchanged in the recon engine.
- Future report work can further improve route-family findings by collapsing high-risk findings under canonical templates such as:
  - `/api/notes/{note_id}`
  - `/api/messages/{message_id}`
  - `/api/orders?user_id={user_id}`
