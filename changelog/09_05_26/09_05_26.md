# Changelog

## ```07-05-26``` ```v2.8.2``` SPA/Fallback, Queue Stability, and Recon Accuracy

### Added

- Added semantic page fingerprinting for SPA, catchall, and redirect fallback detection.
  - Introduced `PageFP` for fallback classification.
  - Page fingerprints include status class, content kind, redirect location, title, H1, asset hash, form hash, body-size bucket, and normalized body hash.
  - Kept `fpString` as the raw exact fingerprint for logs and strict response comparisons.

- Added normalized body hashing for page-level fallback detection.
  - Normalization replaces dynamic JWTs, UUIDs, long hex values, and numeric values before hashing.
  - This helps detect the same SPA shell even when responses contain dynamic nonce/session/timestamp-like values.

- Added bootstrap-route protection for fallback detection.
  - Login/bootstrap routes such as `/login`, `/signin`, `/sign-in`, and `/auth/login` are not skipped as SPA fallbacks.
  - This prevents login endpoints that redirect to home/dashboard from being mistaken for fallback redirects.

- Added identity-specific live identity refresh reasons.
  - Real discovered identities now use refresh reasons such as `live identity refresh:member-uid-2`.
  - This prevents replay probes for different live identities from deduplicating each other.

- Added controlled path-ID expansion by template and base value.
  - Path-ID neighbor probing now avoids the old “first template wins forever” behavior.
  - Each observed base ID can contribute one bounded neighbor expansion without causing infinite path expansion.

### Changed

- SPA/catchall fallback responses are now detected before HTML/JS learning.
  - Fallback responses are logged, but skipped before `Learn`, session capture, response storage, analyzers, and expansion.
  - This prevents SPA shell pages from recursively rediscovering the same links and inflating the discovery graph.

- `runQueuedProbes` now skips analyzers and impact learning for entities already marked as SPA fallback.
  - `Expand` already skipped SPA fallback entities; this makes analyzer behavior consistent with expansion behavior.

- Redirect fallback detection now works for non-200 responses.
  - Redirects to common fallback paths such as `/login`, `/home`, `/signin`, `/sign-in`, and `/auth/login` can be classified as fallback behavior.
  - This improves handling of routes that return `302`, `303`, `307`, or similar redirect responses.

- Login/bootstrap routes are preserved for identity discovery.
  - `/login/bob`, `/login/admin`, and similar endpoints continue to be learned and processed even if their response looks similar to a baseline redirect.
  - This restores discovery of additional live identities after adding early SPA fallback filtering.

- Live identity replay was made explicit.
  - When a new real identity is discovered, already-seen path-ID entities are replayed with an identity-specific refresh reason.
  - This restores stable cross-identity ownership and IDOR evidence after the SPA/fallback cleanup made probing stricter.

- Path-ID family probing now avoids first-winner instability.
  - Previously, `/api/notes/1` or `/api/notes/2` could “win” the whole `/api/notes/{id}` template depending on queue order.
  - The new bounded key uses template + parameter + base value, making probing less dependent on which entity expands first.

- Reduced SPA/catchall graph explosion.
  - SPA fallback routes no longer recursively learn all root shell links/scripts.
  - This greatly reduces noisy edge counts and false public endpoint counts on SPA-style applications.

### Fixed

- Fixed false public endpoint inflation caused by SPA/catchall pages.
  - Client-side routes such as `/random-route`, `/dashboard/settings`, and `/deep/client/side/route` are no longer treated as real public server endpoints when they return the same SPA shell.

- Fixed false admin-surface noise from redirect/fallback behavior.
  - Redirect fallback endpoints no longer become admin surfaces just because they route to public/login/home-style pages.

- Fixed false role boundary on universal `403` endpoints.
  - Endpoints that return `403` to every identity are no longer treated as role boundaries.
  - Role boundary now requires real authenticated permission-denial evidence rather than universal rejection.

- Fixed invalid-bearer probe pollution.
  - Removed the manual `Authorization: Bearer invalid` identity probe from normal identity probing.
  - Invalid bearer testing was causing the normal `session` identity to appear credentialed and generate false role-boundary evidence.
  - Token validation now relies on dedicated synthetic corrupted-token identities instead.

- Fixed stale `SentCreds` preservation.
  - `SentCreds` now reflects the current request instead of being inherited from previous probes.
  - This avoids invalid states such as `IdentityNone creds`.

- Fixed ownership/IDOR regression caused by live identity replay dedupe.
  - Newly discovered real identities now replay against previously seen entities with identity-specific refresh reasons.
  - This restores ownership/IDOR detection on multi-identity test targets.

- Fixed path-ID probing instability caused by one global template lock.
  - The old template-only lock could make report output depend on whether `/api/notes/1` or `/api/notes/2` expanded first.
  - The new bounded path-ID family key reduces this instability while preventing infinite expansion.

- Fixed test instability caused by map iteration in some probe-building paths.
  - Added deterministic ordering where needed for parameter and entity iteration involved in probe generation and refresh.

### Notes

- Report output may still list concrete IDOR URLs such as `/api/notes/1` and `/api/notes/2`.
- A future report-layer improvement should group high-risk findings by route template and parameter, for example:
  - `/api/notes/{note_id}`
  - `/api/messages/{message_id}`
  - `/api/profile?user_id={id}`
- Synthetic identities should eventually be marked clearly in reports, and rejected corrupted-token identities should avoid displaying misleading parsed role/uid claims.
